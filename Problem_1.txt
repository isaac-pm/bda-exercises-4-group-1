DATASET
-------
Marvel Universe Social Network (Kaggle)
- nodes.csv        (node, type): vertex name and type (hero or comic)
- edges.csv        (hero, comic): which heroes appear in which comics
- hero-network.csv (hero1, hero2): hero pairs co-appearing in the same comics

ENVIRONMENT / HOW TO RUN
------------------------
Executed on the IRIS HPC cluster (University of Luxembourg) with Apache
Spark 4.0.1 (Scala 2.13, Java 21) and GraphFrames 0.11.0.

  1. Interactive allocation:
       srun -p batch --time=01:00:00 -N 1 -c 12 --pty bash -i

  2. Load modules:
       module load env/development/2024a
       module load devel/Spark/4.0.1-foss-2024a-Java-21
       module load lang/Python/3.12.3-GCCcore-13.3.0

  3. Install client packages (once):
       pip install --user jupyter
       pip install --user graphframes-py==0.11.0

  4. Environment + start Jupyter on the compute node:
       export PATH=$HOME/.local/bin:$PATH
       export SPARK_HOME=$EBROOTSPARK
       export PYTHONPATH=$SPARK_HOME/python:$(ls $SPARK_HOME/python/lib/py4j-*-src.zip):$PYTHONPATH
       jupyter notebook --no-browser --ip=0.0.0.0 --port=8888

  5. SSH tunnel from the local machine (replace the node name):
       ssh -L 8889:iris-<NNN>.iris-cluster.uni.lux:8888 iris-cluster
       Then open http://localhost:8889/?token=<token>

The SparkSession loads GraphFrames via the Scala-2.13 / Spark-4 package
(matching the cluster's Spark build):

       .config("spark.jars.packages",
               "io.graphframes:graphframes-spark4_2.13:0.11.0")

    Finding: both vertex sets have the same size (19,090) and 19,089 of the
    names match exactly. The only difference is ONE vertex - the Spider-Man
    entry (SPIDER-MAN/PETER PARKER) is stored with a slightly different text
    string in each file (a formatting/whitespace inconsistency in the
    dataset). It therefore appears once as "only in edges.csv" and once as
    "only in nodes.csv", but it refers to the same hero. Conceptually the
    two vertex sets are identical.

(b) CONNECTED COMPONENTS                                         [2 Points]
---------------------------------------------------------------------------
    Total number of connected components:            22
    Largest component size:                          19,029 vertices
    Fraction of vertices in the largest component:   99.68%

    Finding: the Marvel Universe is essentially one giant connected
    component covering 99.68% of all vertices (heroes are linked through
    shared comics). The remaining 21 components are tiny isolated groups
    (sizes 2-11), accounting for only ~0.32% of vertices.

(c) STRUCTURAL METRICS                                           [2 Points]
---------------------------------------------------------------------------
    Vertices:                                        19,090
    Edges:                                           96,104
    Graph density:                                   0.00052745
    Degree - mean:                                   10.07
    Degree - stddev:                                 34.99
    Degree - min / max:                              1 / 1,577
    Highest-degree vertex:                           SPIDER-MAN/PETER PARKER (1,577)
    Average clustering coefficient:                  0.000000
    Approximate average path length (UNDIRECTED):    4.4306  (min 1, max 10)

    Degree distribution: strongly right-skewed (power-law / long tail).
    3,275 vertices have degree 1 and the count falls off steeply, while a
    few hubs reach degrees in the hundreds/thousands (Spider-Man 1,577,
    Captain America 1,334, Iron Man 1,150). Typical of real-world networks.

    Clustering coefficient = 0: this is the CORRECT result for the graph of
    part (a), because it is bipartite (hero <-> comic). A bipartite graph
    contains no triangles by definition, so every local clustering
    coefficient is 0. (Measured on the hero-to-hero projection - the actual
    social network - the clustering coefficient is high, as expected for a
    social graph.)

    Average path length: 4.43 hops on average (sampled BFS from 381 landmark
    vertices, ~2% of the graph). The distribution peaks at distances 4 and 5
    and never exceeds 10:
        distance 1:       3,283 pairs
        distance 2:     288,550
        distance 3:     730,803
        distance 4:   2,889,477
        distance 5:   2,412,813
        distance 6:     767,643
        distance 7:     138,112
        distance 8:      18,049
        distance 9:         860
        distance 10:         78
    Despite having ~19,000 vertices, almost any two are reachable within ~4-5
    hops: a clear SMALL-WORLD structure.

    Graph type: VERY SPARSE but SMALL-WORLD. Density is ~0.0005 (far below
    1), the degree distribution follows a power law dominated by a few hubs,
    almost all vertices form one giant component, and the average path length
    is short (~4.4) - a sparse, hub-centred, small-world network.

(d) PAGERANK vs DEGREE (top-25 per vertex type)                  [2 Points]
---------------------------------------------------------------------------
    PageRank computed on the undirected graph, resetProbability = 0.15,
    maxIter = 10. Degree ranking uses out-degree for heroes (number of
    comics they appear in) and in-degree for comics (number of heroes in
    them); on this graph total degree equals the relevant directional degree
    per type.

    Top hero by PageRank:    CAPTAIN AMERICA        (PR = 103.89)
    Top comic by PageRank:   COC 1                  (PR =   9.55)
    Top hero by degree:      CAPTAIN AMERICA        (degree = 1,334)
    Top comic by degree:     COC 1                  (degree =   111)

    Top-5 heroes by PageRank:
        1. CAPTAIN AMERICA          103.89
        2. IRON MAN/TONY STARK       91.39
        3. HULK/DR. ROBERT BRUCE     75.72
        4. THING/BENJAMIN J. GRIMM   72.11
        5. WOLVERINE/LOGAN           66.92

    Comparison (heroes): the top of both rankings agrees (Captain America,
    Iron Man), but PageRank and degree diverge for several heroes, which is
    exactly the point of the comparison - PageRank measures the QUALITY of
    connections (being linked to central comics/heroes), not just the
    QUANTITY. Notable gaps among the top-25 by PageRank:
        - HULK:               degree rank 7  -> PageRank rank 3
        - PUNISHER II:        degree rank 45 -> PageRank rank 18
        - CAPTAIN BRITAIN:    degree rank 46 -> PageRank rank 22
        - SUB-MARINER:        degree rank 21 -> PageRank rank 13
    These heroes have comparatively few connections, but those connections
    are to highly central hubs, so PageRank ranks them higher than raw
    degree does. Conversely, some high-degree heroes (e.g. Scarlet Witch,
    Beast) drop slightly under PageRank.

(e) HERO CO-OCCURRENCE PAIRS                                     [2 Points]
---------------------------------------------------------------------------
    Pairs computed from edges.csv (distinct, canonical order):  171,644
    Rows in hero-network.csv (with multiplicity):               574,467
    Distinct normalized pairs in hero-network.csv:              167,219
    Pairs in BOTH:                                              138,450
    Only in our computation (not in hero-network.csv):           33,194
    Only in hero-network.csv (not in our computation):           28,769

    Finding: both datasets describe the same underlying hero-to-hero
    network - the 138,450 shared pairs represent ~81% of our pairs and ~83%
    of the file's pairs. They are NOT identical, however, and neither is a
    strict subset of the other. The mismatches are explained by:
      (1) Name-string inconsistencies in the raw data (the same Spider-Man
          discrepancy found in part (a), and similar formatting differences),
          which prevent some pairs from matching exactly.
      (2) hero-network.csv being generated from a slightly different
          processing of the comic appearances than edges.csv, so a number of
          pairs exist on one side only.
    hero-network.csv also stores one row per co-appearance (574,467 rows),
    which collapses to 167,219 unique unordered pairs after normalization.
